Jig · monorepo architecture

Build Pipeline

How a colour written as an OKLCH triple in TypeScript becomes a custom property in a published stylesheet — and every gate it has to pass on the way.

01Tokens to package

Four stages, each one a workspace package that builds only after the one above it. The columns hold across every stage: what a person wrote, what transforms it, and what lands on disk. Nothing in the right-hand column is committed except the icons, which are generated and tracked so that drift between the two is detectable.

02Packages at a glance

One package is published. The other two exist to be compiled away — their output is bundled into @jig-ui/react, so the published package has no runtime dependencies beyond React itself.

Package Role Produces Status
@jig-ui/tokens Authors primitives and semantics in TypeScript; validates aliases, cycles, light/dark parity and required semantics before anything is written. *.dtcg.json + resolver private
@jig-ui/styles Runs Terrazzo over the resolver to emit four theme permutations, strips the redundant declarations, and builds the optional reset. tokens.css · vars.js · reset.css private
@jig-ui/react The components. Bundles the token values in, emits a declaration tree, and composes the single layered stylesheet consumers import. ESM · d.ts tree · styles.css published
@jig-ui/tsconfig Shared TypeScript base configs for node and library targets. *.json private

03How the stylesheet is assembled

styles.css is not a concatenation — it is a declared cascade. Every Jig rule sits inside a layer, which means unlayered CSS in a consumer's app beats all of it regardless of selector specificity. Overriding a token does not require out-specifying :root[data-theme="dark"].

04Where it can fail closed

Three independent gates, each covering a path the others miss. The local one matters because maintainers and release tooling invoke package scripts directly, without Turbo in front of them.

  • The packed-consumer test installs the real tarball into an isolated project and type-checks it, which is the only check that sees a broken export map or a declaration importing a private workspace package.
  • Icons are generated but committed; check:icons regenerates and fails if anything moved.
  • Token validation runs inside the tokens build, so an unresolvable alias or a light/dark parity gap stops the pipeline at stage one.
